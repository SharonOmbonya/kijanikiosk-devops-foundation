# KijaniKiosk Deployment Demonstration Script

[Stage direction: The demonstration begins with the current version running normally. The team shows the board that a new release is ready to be introduced.]

Nia:
Today we are demonstrating how KijaniKiosk can release a new version safely and recover automatically if a problem occurs. The goal is to show that customer service can continue even when a release does not behave as expected.

[Stage direction: The new version is deployed and traffic is switched to the updated environment.]

Nia:
The new version has been prepared and traffic has been moved to it. Customers are now being served by the updated release.

[Stage direction: A controlled failure is introduced in the new environment.]

Nia:
We are now introducing a planned fault to confirm that the system can detect a problem and recover without waiting for a person to respond.

[Stage direction: The monitoring system detects failures and automatically restores the previous working version.]

Nia:
The system detected the problem and restored the previous working version automatically. No manual recovery action was required.

[Stage direction: The final service check confirms the previous version is serving successfully.]

Nia:
The recovery completed in 15 seconds. This reduces the time customers could experience disruption and gives the team confidence that the release process can protect service availability.
